# How Can One Sample Tell Us About an Entire Population?

This project uses simulated monthly household spending to explain how one sample supports statistical inference. It reproduces the bootstrap confidence interval, repeated-sample coverage experiment and simulated hypothesis test in [Blog 8](https://xia071212.github.io/myrepo/blog/posts/post8/).

## Data and sources

All observations are generated by the Python script; no external survey or download is required. The population contains 20,000 households. Spending follows a right-skewed lognormal shape with log standard deviation 0.45, rescaled so the population mean equals $3,000. Values are monthly dollars per household and do not describe an actual city.

| File in `data/` | Fields | Use |
|---|---|---|
| `population.csv` | `household_id`, `monthly_spending` | Complete simulated population; Figure 1 and repeated surveys |
| `sample.csv` | `draw_id`, `household_id`, `monthly_spending` | The 150 distinct households in the observed survey; Figure 2 and bootstrap input |

Both files are generated and saved during reproduction. There are no missing observations, joins or additional cleaning steps.

## Definitions and simulation design

The observed survey draws 150 households without replacement. Bootstrap resampling draws 150 observations **with replacement from that survey**, repeated B = 1,200 times. The central 95% of bootstrap means defines the percentile interval. Quantiles interpolate between adjacent ordered values.

Coverage uses R = 1,000 independent surveys, each with its own bootstrap interval. Coverage is the proportion containing the fixed population mean; all R intervals enter the calculation, while Figure 4 displays the first 100. At baseline, 941 intervals cover the mean (94.1%). B controls resamples per interval; R controls the number of intervals used to assess coverage.

The two-sided test compares the observed statistic, t = (sample mean − null mean)/(sample standard deviation/√n), with 10,000 statistics simulated under a $3,000 null mean. Each null survey recalculates its standard error. The p-value is (extreme simulations + 1)/(10,000 + 1), counting absolute statistics at least as large as the observed absolute statistic. Reject when p ≤ 0.05. The baseline p-value is 0.68583, so the null is not rejected.

Null surveys retain the population shape and rescale its mean to the null value. This is a model-specific simulation test. The ordinary bootstrap and s/√n standard error approximate sampling uncertainty without a finite-population correction; the baseline sample is 0.75% of the population. Percentile intervals have approximate, rather than guaranteed, coverage.

The population seed is 71023. The simulation seed is 20261101, with separate offsets for the survey, bootstrap, coverage and null experiments. The Python random-stream implementation matches the published JavaScript stream, so the saved results reproduce the website baseline up to floating-point rounding.

## Code and their roles

The complete workflow is written in [code/reproduce.py](code/reproduce.py), with four numbered stages: **Setup → generate and save data → analyze and save results → create and save figures**. Paths resolve relative to the project, output folders are created automatically, and parameters and random streams are defined together.

| Code | Purpose |
|---|---|
| [code/reproduce.py](code/reproduce.py) | Main workflow: population, survey, bootstrap interval, independent coverage experiments, null simulation, saved tables and six figures |
| [code/simulation.py](code/simulation.py) | Random stream, sampling, bootstrap, descriptive statistics, percentiles and test calculations |
| [code/figures.py](code/figures.py) | SVG plotting functions matching the article's axes, labels, colors and shading |
| [code/verify.py](code/verify.py) | Checks sampling, quantiles, interval nesting and hypothesis-test calculations |

The website's JavaScript interaction, page layout and decorative illustration are maintained in the [website repository](https://github.com/xia071212/myrepo/tree/main/blog/posts/post8). Reproducing this analysis does not edit, render or publish the blog and does not require Node.js or Quarto.

## Reproducing the analysis

1. Download the repository with `code/`, `data/` and `results/` intact. Prepare Python with NumPy, listed in `requirements.txt`. Tested with Python 3.9.6 and NumPy 2.0.2.
2. Open `code/reproduce.py` to follow its four commented stages, then run the file with Python. It runs from any working directory and generates the complete analysis without network access.
3. Inspect the generated population and sample in `data/`, tables in `results/tables/`, and six SVG images in `results/figures/`. Open an SVG in a browser to view it.
4. Run `code/verify.py` with Python to check the statistical helper functions.
